SMS Spam Detection Agent

A Linear SVM classifier upgraded with an AI agent layer — not just a verdict, but an explanation and a plan.

How It Works

This project adds an AI reasoning layer on top of a trained Linear SVM classifier. The model handles classification; the agent handles explanation. Neither could do the other's job — the combination is what makes this useful.

01
User pastes SMS message
02
Agent calls classifier tool
03
SVM returns verdict + confidence
04
Agent explains in plain English
05
Agent recommends next steps

Text preprocessing matches training conditions exactly — URLs, emails, phone numbers, and money amounts are replaced with placeholder tokens before classification. Skipping this step would mean the model sees messages in a different form than it was trained on, which matters most for spam content that typically contains links and prices.

Model Selection

Four models were trained and compared. Linear SVM was selected — not because it had the highest raw F1, but because its cross-validated score is a more reliable estimate than a single train/val/test split.

Model Spam F1 Accuracy CV Mean F1
Linear SVM ✓ 0.942 98.6% 0.971 ± 0.007
Logistic Regression 0.938 98.5% 0.967 ± 0.004
CNN (Conv1D) 0.949 98.7% N/A — single split
BiLSTM 0.930 98.3% N/A — single split

A majority-class baseline (predicting ham for every message) reaches 87% accuracy purely from class imbalance — but catches zero spam. This is why Spam F1 was used as the primary metric, not accuracy.

Honest Findings

Testing the deployed agent revealed two cases where the model's 2012 training data diverges from modern message patterns — both documented below as research findings rather than failures.

Dataset Drift — Telecom Roaming Notifications

A legitimate MTN Ghana roaming notification was classified as spam with high confidence. The message contained precise per-minute pricing and a phone number — patterns the 2012 training data associates strongly with promotional spam. Modern telecom notifications were not part of the SMS Spam Collection dataset.

Dataset Drift — Delivery Phishing

A classic delivery phishing message ("Your parcel could not be delivered — confirm your address at delivery-info.com") was classified as ham. Delivery notification scams became widespread after 2015; the training data predates this pattern entirely.

Agent Layer as Partial Compensation

In both cases, the AI agent added cautionary reasoning that partially compensated for the model's error — flagging the suspicious domain in the phishing case and noting the unusual pricing format in the roaming case. The agent cannot override the classifier, but it can flag uncertainty and advise caution where the model is confident but the context is ambiguous.

Connection to Dissertation Research

These findings mirror the vocabulary cliff effect documented in my MSc dissertation — where out-of-distribution vocabulary causes model performance to degrade sharply. Modern spam terminology (delivery-info, roaming rates) falls outside the classifier's learned vocabulary distribution, producing the same misclassification pattern observed when cleaning removes rare tokens from NLP training data.

What the Agent Layer Adds

The original classifier returns a label and a score. The agent version returns a conversation.

  • Plain-English explanation of why the message looks like spam or ham
  • Confidence interpretation — very high, high, moderate, or borderline
  • Specific recommended actions tailored to the damage type
  • Conversational interface — users can check multiple messages in one session
  • Honest uncertainty flagging when confidence is low
